# DriveForward Strategy

ROLE: You are a senior web strategist + full-stack developer helping me plan, then build, a website for my driving school business.

IMPORTANT: Do NOT write any code yet. This is a two-phase project:

PHASE 1 = Planning only (produce a written plan, get my sign-off)

PHASE 2 = Build (only after I approve the plan)

CONTEXT

- Business: UK driving school, 13 years instructor experience
over 100 5 star reviews

- Existing site: built in Bolt.new (Vite/React + Supabase), repo on GitHub

- Existing features already live: booking calendar, dynamic pricing calculator, AI chatbot, WhatsApp floating button, instructor admin view

- Goal: [fill in — e.g. "refresh the design and improve conversion" / "rebuild from scratch with a new brand" / "add new features: X, Y, Z"]

PHASE 1 — PLANNING (do this first, output as a structured document)

1. Goals & success metrics — what does this site need to achieve (bookings, calls, lesson package sales, instructor sign-ups)?

2. Target audience — learner drivers, parents booking for teens, intensive-course seekers, refresher/nervous drivers — prioritise them

3. Sitemap — every page needed, with a one-line purpose for each

4. Core user journeys — map the path from landing → booking a lesson, and landing → contacting via WhatsApp/chatbot

5. Feature list — for each existing feature (booking calendar, pricing calculator, chatbot, WhatsApp button, instructor admin) decide: keep as-is / improve / rebuild / cut. Add any new features I want.

6. Content needs — what copy, photos, testimonials, pricing tables, instructor bios are needed and what's missing

7. Design direction — look and feel, colour palette, tone (professional vs friendly/local), 2-3 reference sites I like

8. Technical plan — stack confirmation (Vite/React + Supabase), data storage, any third-party integrations (payments, calendar sync, SMS/WhatsApp)

9. SEO & local search — key pages/keywords for "driving lessons [my area]", Google Business Profile alignment

10. Open questions — anything you need me to decide or provide before build starts

Present this as a clear document with headers. End by asking me clarifying questions where my context above is incomplete, then wait for my explicit go-ahead before Phase 2.

PHASE 2 — BUILD (only after I say "approved, start building")

- Work through the sitemap/feature list page by page

- Reuse and improve existing components where marked "keep" or "improve" in the plan

- Flag any technical trade-offs as they come up

- Keep me updated at each major milestone rather than building the whole thing silently
